# [Feat] 기존 AI 채팅 기반 상담사 연결 및 상담 보호·이력 관리 구현

## 🌐 관련 도메인

- Counsel, Conversation, Auth, User, Admin, Embedding, Data Retention

## ✨ 기능 설명

- 기존 UBot-BE의 `com.ubot.counsel`에 상담 요청·배정·메시지·검사·관리자 API를 통합한다.
- 로그인한 회원만 본인 대화에서 상담을 요청하도록 제한하고, COUNSELOR 역할과 상담 가능 상태를 관리한다.
- FIFO 대기열 배정, 상담사 heartbeat, 연결 복구·재배정, 대기 취소·상담 종료를 처리한다.
- 연결 요청 시 해당 대화의 기존 고객·AI 문답과 화면 보충 기록을 저장해 담당 상담사에게 전달한다. 재상담 시 이전 상담의 허용된 메시지도 이어받는다.
- 상담 요청과 메시지 전송의 중복 처리를 방지하고, 현재 참여자만 조회·전송할 수 있도록 권한을 검증한다. 재배정되면 이전 상담사의 접근을 회수한다.
- 신규 상담 메시지를 검사하고 ALLOWED 메시지만 전달한다. BLOCKED·CHECK_FAILED 메시지는 상대방에게 전달하지 않는다.
- 기존 ai-worker의 상담 전용 Redis 큐와 별도 소비 스레드에서 vLLM BGE-M3 임베딩을 수행한다.
- 관리자용 금지 문장 목록·상세 조회, 등록·수정·삭제, 임베딩 색인·재색인, 가드 평가 API를 제공한다. revision 검증으로 수정·삭제 전의 오래된 색인 결과가 반영되지 않도록 한다.
- 관리자용 상담사 역할 관리와 검사 이벤트·판정 집계 조회 API를 제공한다.
- AI 질문 없이 시작한 상담도 기존 회원 대화에 연결한다. 기존 대화 목록에 상담 포함 여부·미리보기·최근 활동을 반영하고, AI·고객·상담사 메시지와 연결·종료 표시를 통합 이력으로 조회한다.
- 통합 이력의 페이지 조회와 반복 인계 사본 중복 제거를 지원하고, V39 마이그레이션 하나로 상담 스키마 생성·기존 데이터 인계·과거 대화 연결을 처리한다.
- 기존 보관 작업에 상담 데이터를 연계한다. 종료 대화는 마지막 활동 후 3개월, 차단·검사 실패 기록은 생성 후 3개월 기준으로 삭제하며 진행 중 상담은 보존한다. 회원·상담사 탈퇴에 따른 정리도 처리한다.

## 💡 특이사항

- 기존 JWT, ApiResponse, 예외 처리, DB·Redis 및 ConversationService를 재사용한다. 기존 AI 채팅 큐와 AI 문답 조회 API 계약은 유지한다.
- 상담사는 연결된 대화의 인계 기록을 확인한다. 회원의 다른 모든 대화가 공유되는 것은 아니다. 고객의 통합 이력 API는 본인 대화만 조회할 수 있다.
- 최신 develop(`348a447`)의 Outbox·고객센터 문의 구현을 반영했다. develop의 V37·V38 다음에 상담 V39 하나를 적용한다.
- BE 회귀 테스트 780건 중 775건 통과, 기존 환경 조건에 따른 제외 5건, 실패·오류 0건을 확인했다.
- 실제 고객·상담사 계정의 연결과 양방향 메시지 저장, 로그아웃·재로그인 후 기존 목록을 통한 이력 복원을 확인했다. 관리자 금지 문장 API와 실제 워커/vLLM 색인·판정도 검증했다.
- 기존 AI 문답은 저장된 테스트 데이터로 검증했다. AI 답변 실시간 생성과 공유 GPU 부하에 따른 성능 검증은 별도 범위다.
- 상세 API와 검증 결과는 [상담 도메인 문서](../how-to/counsel.md), [검증 기록](../counsel-verification.md)을 참고한다.
