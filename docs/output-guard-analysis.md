# 출력 가드 오탐 원인과 하위 답변 보존 가능성

출력 가드가 문장을 지우거나 칸을 거부한 하위 답변을 두 관점에서 분석한 내용입니다.

1. **오탐 원인** — 가드가 근거에 있는 정상 답변까지 제거하는 규칙별 원인과 개선 제안
2. **하위 답변 보존** — 문장이 제거된 뒤 남은 본문으로 하위 답변을 살릴 수 있는지

두 분석 모두 66칸 규모를 대상으로 합니다. 2부는 v6 32칸 + on-broken 34칸을 다시 추출했으며([2.1 자료와 방법](#21-자료와-방법)), 1부(과거 분석)의 66칸과 개별 항목이 같은지는 확인하지 않았습니다.

> 1부의 건수는 기존 분석 결과를 정리한 값이며 이번 문서 작성에서 재집계하지 않았습니다. 2부의 분류는 수동 검토입니다. 두 분석 모두 가드·운영 코드는 수정하지 않았고, 코드 위치는 분석 당시 기준이라 변경될 수 있습니다.

## 요약

- **오탐 원인:** 수량의 대상·조건을 구분하지 않는 비교(`QUANTITY_CONFLICT` 16칸), 표현 차이에 민감한 제한 판정(`UNSUPPORTED_RESTRICTION` 16칸), 회원의 과거 기록을 봇의 처리 완료로 해석하는 패턴(`UNSUPPORTED_OPERATION`/`FALSE_EXECUTION` 5칸). 규칙 간 중복을 빼면 직접 영향은 최대 34칸입니다.
- **하위 답변 보존:** `contentRemoved=true`면 하위 답변 전체를 폐기하는 정책은 일부 정상 답변 손실을 키웁니다. 그러나 남은 본문에도 환각·범위 혼동·핵심 답 누락이 있어, `rejected=false`이고 본문이 남았다는 이유만으로 모두 살리면 안 됩니다. 66칸 중 보존 후보는 11칸(중복 제거 7칸·6문항)입니다.
- **우선 할 일:** 오탐은 가드 규칙 자체를 고치고, 보존은 "독립적인 부가 설명만 지워지고 핵심 답·조건은 근거에 맞게 남은 경우"로 좁혀 검토합니다. 삭제 사유 하나만으로 허용 여부를 정할 수는 없습니다.

# 1부. 출력 가드 오탐 원인 및 개선 제안

## 1.1 QUANTITY_CONFLICT — 오탐 16칸

### 현재 동작

- `readFacts`: 숫자 앞 16자 안의 항목어(요금·할인·데이터·기간 등)를 연결합니다. 없으면 뒤 3자 안을 확인하고, 항목어가 없는 숫자는 버립니다.
- `hasQuantityConflict`: 답변과 근거의 항목·단위가 같은 숫자를 모아, 같은 값이 하나도 없으면 충돌로 판단합니다.
- 비교 근거는 전달한 FAQ·섹션 전체입니다. 어떤 상품의 값인지, 어떤 조건의 값인지는 구분하지 않습니다.

### 원인 A: 목록형 근거의 일부 숫자만 인식 — FAQ 9칸

FAQ 298:

> 2회선이면 대표 회선에서 월 6,000원, 3회선이면 월 15,000원, 4회선이면 월 20,000원, 5회선이면 월 24,000원을 할인합니다.

앞의 6,000원·15,000원·20,000원에는 가까운 항목어가 없어 버리고, 마지막 값만 `할인 = 24,000원`으로 인식합니다. 그래서 정상 답변인 “가족 결합 2회선은 월 6,000원을 할인합니다”를 충돌로 처리합니다. 재현에서는 5회선 24,000원만 통과했습니다.

워치 FAQ 1117도 같은 문제입니다.

> Ubot 워치 요금제는 0.5GB(월 5,500원, …), 1GB(8,800원, …), 2GB(11,000원, …)

“요금” 근처의 5,500원만 요금으로 잡혀 1GB 8,800원 안내가 제거됩니다. 반면 답변을 “1GB는 8,800원입니다”로 쓰면 답변 숫자에도 항목어가 없어 비교를 건너뛰고 통과합니다.

해당 문항: MA-005(2칸), MA-016(2칸), MP-029(2칸), MT-004, MT-025, OS-022, SA-041. 문항 목록에는 다른 원인과 겹치는 사례가 포함될 수 있습니다.

### 원인 B: 다른 상품의 숫자와 비교 — FAQ 4칸

- MP-019: 비디오패스의 월 9,900원이 근거에서 항목어 없이 버려지고, 같이 전달된 IPTV의 월 16,500원과 비교됩니다.
- MA-034(2칸): “500Mbps 기준 월 5,500원 할인”을 함께 전달된 가족 결합의 24,000원 할인과 비교합니다.

### 원인 C: 회원 기록 대조 — 3칸

- UD-026: 요금제 이름 `Ubot 밸런스 59 75GB업` 안의 75GB를 데이터 수치로 읽어 실제 제공량 96.7GB와 충돌합니다. 다만 “기본 데이터 75GB”라는 실제 오류가 있는 칸과 쉐어링 칸이 섞여 있어 구분이 필요합니다.
- UD-029의 월 48,125원(할부 월납부액)과 UD-027은 회원 기록 대조 경로에서 걸린 것으로 추정됩니다. 독립적인 단위 재현은 하지 않아 원인 추가 확인이 필요합니다.

### 개선 제안

1. 수량을 **대상 + 조건 + 항목 + 단위 + 값**으로 묶습니다.
2. 대상·조건이 같은 근거끼리 비교합니다. 다른 대상의 근거는 비교 불가로 처리하고 충돌 근거로 사용하지 않습니다.
3. 목록의 공통 항목어를 각 값에 연결하되, `2회선 → 할인 6,000원`처럼 조건과 값을 반드시 짝지어 보존합니다.
4. 회원 기록 3칸은 `UserRecordClaims`에서 별도로 검토합니다.

**주의:** 목록의 숫자를 모두 허용하기만 하면 “2회선은 15,000원” 같은 실제 오답도 통과합니다.

수정 대상: `readFacts`, `hasQuantityConflict`(FAQ 13칸), `UserRecordClaims`(회원 기록 3칸).

## 1.2 UNSUPPORTED_RESTRICTION — 오탐 16칸

### 현재 동작

- 답변의 불가 표현(“할 수 없습니다”, “제공하지 않습니다” 등)을 찾습니다.
- 불가 표현 앞부분을 정규화해 `주제 | 행위` 키를 만듭니다.
- FAQ·섹션의 불가 문장에서도 같은 방식으로 근거 키를 만듭니다.
- 같은 키가 없으면 답변 문장을 제거합니다. 생략 허용은 답변이 근거보다 짧을 때만 적용됩니다.

### 원인 A: 주어·수식어 차이로 키가 어긋남 — 9칸

- MA-014
  - FAQ: “키즈 안심 가입에는 법정대리인 동의가 필요하고 테더링은 제공하지 않습니다.”
  - 답변: “키즈 안심 요금제는 테더링을 제공하지 않습니다.”
- MP-043
  - FAQ: “엠세이퍼 가입 제한이 걸려 있으면 본인도 … 개통할 수 없습니다.”
  - 답변: “이 제한이 걸려 있으면 본인도 새 휴대폰을 개통할 수 없습니다.”
- MA-015(3칸)
  - FAQ: “태블릿 요금제는 5GB 월 9,900원부터 …까지 있으며 음성·문자는 제공하지 않습니다.”
  - 답변: “태블릿 요금제는 데이터 전용 상품으로 음성·문자는 제공하지 않습니다.”

같은 이유로 MA-024, MA-006(변경 ↔ 바꿀), ST-023(2칸)도 제거됐습니다. 재현에서는 FAQ 절을 그대로 쓰면 통과하고 주어만 바꾸면 제거됐습니다.

### 원인 B: 한정형 근거를 부정형으로 바꿔 말함 — 7칸

- MA-020(4칸): “방문 시간 전까지만 취소 가능” → “방문 시간이 지나면 취소 불가”
- MA-025: “발급 후 7일 안에 사용” → “7일 이후 사용 불가”
- SA-023: “회선별로 가입해야 함” → “한 번만 가입하는 것은 불가능”
- SA-024: “해외 로밍 데이터에는 적용되지 않음” → “국내 데이터 충전으로 로밍을 대신 쓸 수 없음”

이 묶음에는 한정형을 부정형으로 바꾼 사례와 적용 대상을 다른 표현으로 바꾼 사례가 함께 있습니다. 특히 긍정·한정형 문장은 불가 표현이 없어 근거 키로 등록되지 않습니다.

### 개선 제안

1. 주제는 문장 앞부분 전체가 아닌 **대상 + 행위** 중심으로 비교하고 수식어는 분리합니다.
2. “이 제한” 같은 지시어를 질문이나 앞 문장의 대상으로 연결합니다.
3. “전까지만 가능”, “7일 안에 사용” 같은 한정형도 조건부 불가 근거로 인식합니다.
4. 조건을 키에 보존합니다. “방문 시간 이후 취소 불가”를 “항상 취소 불가”로 확대해서는 안 됩니다.

수정 대상: `restrictionTopic`, `addRestrictionEvidence`.

## 1.3 UNSUPPORTED_OPERATION / FALSE_EXECUTION — 오탐 5칸

### 현재 동작

`hasUnsupportedOperation`은 가입·납부·결제·변경·신청 등의 업무어 뒤 30자 안에 과거·완료 표현이 있으면 봇이 업무를 처리했다고 판단합니다. 회원 정보 예외는 그 뒤의 조회 주장 검사에만 적용돼, 업무 완료 검사에는 적용되지 않습니다.

### 주요 사례

- UD-004: “평가회원은 2024-03-15에 Ubot에 **가입했습니다**.”
- UD-001(1차): “2026년 10월 20일에 회원 **가입했으며**…”
- UD-009: “10월 청구서도 … 자동이체로 **완료되었으며**, 미납 내역이 없습니다.”
- UD-012: “24개월 중 19개월 **납부했고**…”
- CQ-022: “… 납부 완료로 기록 … 자동이체로 **처리되었습니다**.”

제공된 회원 기록을 전달한 과거형 문장을 봇의 실행 주장으로 오인합니다. 회원 기록 섹션이 추가되기 전의 패턴이 이 경우를 충분히 고려하지 못했을 가능성이 있습니다.

### 개선 제안

1. 회원 정보·도구 기록의 **업무·날짜·상태와 일치하는 서술**은 업무 완료 검사에서 예외로 처리합니다.
2. 가입일, 청구서 납부 완료, 할부 납부 개월 수 등을 대조합니다.
3. “가입해 드렸습니다”, “처리해 드렸습니다”처럼 봇이 실행 주체인 표현은 계속 차단합니다.

수정 대상: `hasUnsupportedOperation`의 업무 완료 검사.

## 1.4 영향 범위

- 규칙별 오탐은 **16 + 16 + 5 = 37칸**입니다.
- 규칙 간 중복을 제외한 직접 영향 대상은 **최대 34칸**입니다.
- 모든 대상이 수정으로 회복된다는 의미는 아닙니다. 같은 칸에 다른 차단 사유가 남아 있을 수 있습니다.

# 2부. 문장 제거 후 하위 답변 보존 가능성

## 2.1 자료와 방법

- v6: `pipeline_test_v6/try1/results/raw/local-win_qwen3-4b-instruct_t0_pv6_feat277lines_n172_20261023/results.jsonl`
- on-broken: `pipeline_test_v7/try1/results/raw/local-win_qwen3-4b-instruct_t0_pv7_onbroken_n172_20261023/results.jsonl`
- 두 실행의 **최종 턴**에서 `output_guard_checks`의 `content_removed` 또는 `rejected`가 참인 칸을 추출했습니다. 중간 대화 턴은 제외했습니다.
- 이번에 재구성한 대상은 v6 32칸 + on-broken 34칸 = 66칸입니다. 1부(과거 분석)의 66칸과 개별 항목이 동일한지는 확인하지 않았습니다.
- 기존 가드가 기록한 입력·제거 후 본문·FAQ·회원 정보·도구 결과를 대조했습니다. 기존 문장을 재조합하거나 다시 생성하지 않았습니다.
- 분류는 수동 검토입니다. 제거 후 본문을 새 LLM Judge로 평가하지 않았으므로 정답률 개선 수치로 해석하지 않습니다.
- 두 실행에는 같은 문항·칸이 반복됩니다. 합산 건수는 고유 질문 수가 아닙니다.

## 2.2 on-broken 결과: 34칸

- **보존 후보 4칸:** 해당 질문의 유효한 핵심 답이 남아 있음.
- **핵심 답·조건·범위 손실 8칸:** 본문은 있지만 해당 칸의 답으로 그대로 유지하기 어려움.
- **오답·근거 없는 주장·문맥 손상 잔존 9칸:** 문장 제거 후에도 위험한 내용이 남음.
- **전체 거부 또는 잔여 본문 없음 13칸:** 호출부의 전체 폐기 조건만 완화해도 살릴 본문이 없음.

즉, 잔여 본문이 있는 21칸 중 보존 후보는 4칸입니다. 나머지 17칸을 그대로 유지하는 것은 권하지 않습니다.

### 보존 후보 4칸

1. **MA-015 / 1번 칸 — 태블릿 20GB 가격**
   - 입력: “태블릿 요금제 20GB 가격은 월 19,900원입니다. 음성통화는 … 제공되지 않으며 …”
   - 제거 후: “태블릿 요금제 20GB 가격은 월 19,900원입니다.”
   - 첫 칸은 가격 질문입니다. 다른 하위 질문의 음성통화 설명이 제거돼도 가격 답은 독립적으로 남습니다.
2. **MA-015 / 2번 칸 — 음성통화 제공 여부**
   - 제거 후: “데이터 전용 요금제이므로 음성 통화 기능이 없습니다.”
   - 중복된 부정 표현 하나가 제거돼도 동일한 결론이 남습니다.
   - 전체 전달 자료에는 음성·문자 미제공 근거가 있습니다. 다만 두 번째 칸의 FAQ 묶음 자체에는 그 근거가 없어, 실제 자동 보존 설계에서는 칸별 근거 범위 문제를 따로 확인해야 합니다.
3. **UD-009 / 1번 칸 — 미납 여부**
   - 제거 후: “아니요, 밀린 요금이 없습니다. 2026년 9월 청구서(8월 사용분) 기준으로 … 해당 청구서는 자동이체로 완료되었습니다.”
   - 회원 정보의 미납 없음과 도구로 조회한 청구서 기록이 핵심 답을 뒷받침합니다. 반복된 최근 납부 설명을 제거해도 답이 남습니다.
4. **UD-026 / 1번 칸 — 기본 데이터량**
   - 제거 후: “제 요금제 기본 데이터는 96.7GB입니다.”
   - 실제 회원 정보와 같은 값입니다. 상품명·부가 설명을 제거해도 핵심 수량은 남습니다.

이 목록은 자동 보존 정책이 검증됐다는 뜻이 아니라, 회귀 테스트로 고정할 보존 후보입니다.

### 본문이 있어도 유지하기 어려운 사례

**핵심 답이 사라짐 — MA-016 / 1번 칸**

- 질문: 워치 1GB 월 요금.
- 삭제된 내용: “월 8,800원”(1.1 원인 A의 오탐).
- 잔여 본문: “이 요금제는 음성 100분, 문자 250건을 제공합니다.”
- 문장은 정상이어도 월 요금에 답하지 않습니다. ANSWER로 유지할 근거가 부족합니다.

**필수 제한이 사라짐 — MA-020 / 1번 칸**

- 잔여 본문은 앱에서 취소하는 방법을 안내합니다.
- “방문 시간 이후 취소 불가”가 제거돼(1.2 원인 B의 오탐), 취소 가능 시간의 경계가 빠졌습니다.
- 취소 방법 자체는 맞아도 허용 범위를 넓게 읽을 수 있어 보수적으로 전체 폐기 대상으로 분류했습니다.

**다른 하위 질문의 답만 남음 — UD-025 / 1번 칸**

- 첫 질문은 본인의 2개월 미납 여부입니다.
- 잔여 본문은 “미납하면 다음 날 안내 문자 발송”이라는 일반 정책입니다.
- 근거 있는 문장이어도 해당 칸의 답이 아닙니다.

**잘못된 결론만 남음 — MP-029 / 1번 칸**

- 정상 가격인 “워치 2GB 월 11,000원”이 제거됐습니다.
- 잔여 본문은 “개통비는 따로 없습니다.”입니다.
- 전달 FAQ에는 개통비 무료 근거가 없습니다. 이 상태를 유지하면 정상 가격 대신 환각만 출력합니다.

**틀린 답이 더 단정적으로 남음 — MT-006 / 1번 칸**

- 잔여 본문: “그 요금제 무제한은 월 68,000원입니다.”
- 실제 회원 요금제는 데이터 96.7GB 제공 상품이며, 삭제된 설명이 이 차이를 드러내고 있었습니다.
- 남은 한 문장이 자연스럽다는 이유로 보존하면 오답이 강화됩니다.

**근거 없는 답은 그대로 남음 — UD-015 / 1번 칸**

- 잔여 본문: “제 멤버십 등급은 골드입니다.”
- 실제 등급 또는 산정에 필요한 직전 6개월 평균 요금이 제공되지 않았습니다.
- 잘못된 산정 설명만 지워도 결론이 검증되는 것은 아닙니다.

## 2.3 v6를 함께 본 결과

- v6 32칸: 보존 후보 7 / 핵심·범위 손실 8 / 오답·문맥 손상 잔존 10 / 잔여 없음 7.
- on-broken 34칸: 보존 후보 4 / 핵심·범위 손실 8 / 오답·문맥 손상 잔존 9 / 잔여 없음 13.
- 합산 66칸: **보존 후보 11 / 핵심·범위 손실 16 / 오답·문맥 손상 잔존 19 / 잔여 없음 20**.
- 보존 후보 11개 실행 기록의 문항·칸 중복을 제거하면 **7칸·6문항**입니다.
- 고유 후보: MA-004:1, MA-015:1, MA-015:2, SA-019:1, SA-038:1, UD-009:1, UD-026:1.

v6의 추가 후보 중 SA-019는 “넘버플러스 월 요금 3,300원” 뒤의 잘못된 청구서 출처 설명만 제거한 경우입니다. SA-038은 근거 없는 개인 등급 추론을 제거하고 VIP/GOLD/SILVER의 일반 등급 안내를 남긴 경우입니다.

## 2.4 사유별 허용을 설계할 때의 한계

현재 기록된 `OutputGuardResult.Reason`은 `ANSWER_ERROR`, `FALSE_EXECUTION`, `FAQ_SHORTAGE_SUSPECTED` 같은 넓은 분류입니다. `QUANTITY_CONFLICT`와 `UNSUPPORTED_RESTRICTION` 등 세부 규칙은 내부 `GuardRule`에 있습니다. 이번 JSON trace만으로 모든 칸을 세부 규칙별로 정확히 재집계할 수는 없습니다.

- on-broken의 `ANSWER_ERROR` 29칸 중 보존 후보는 3칸입니다. 같은 사유에 핵심 손실·환각 잔존이 함께 있습니다.
- `FALSE_EXECUTION` 6칸 중 보존 후보는 1칸입니다. 1칸은 오답 잔존, 1칸은 범위 손실, 3칸은 전체 거부·잔여 없음입니다.
- 사유는 한 칸에 여러 개 붙으므로 사유별 합계는 중복됩니다.
- 따라서 `FALSE_EXECUTION이면 유지`, `수량 충돌이면 유지` 같은 일괄 허용은 근거가 부족합니다.

## 2.5 제안하는 처리 기준

### 보존 검토 가능

다음 조건을 모두 확인한 경우입니다.

1. 전체 거부가 아니고 잔여 본문이 있음.
2. 제거된 문장이 핵심 답·조건·예외가 아닌 독립적인 부가 설명임.
3. 잔여 본문이 현재 하위 질문에 직접 답함.
4. 남은 주장에 실제 근거가 있고, 삭제한 주장에 의존하지 않음.
5. 삭제 때문에 허용 범위가 넓어지거나 비교·추천·결론이 뒤집히지 않음.

독립적인 잘못된 출처 설명, 반복된 회원 기록 서술, 다른 질문에 대한 덧붙임 제거를 우선 후보로 삼을 수 있습니다. 세부 규칙 이름만으로 이 조건들이 자동 충족되는 것은 아닙니다.

### 전체 폐기 유지

- 정책 위반·형식 거부 등 전체 거부.
- 핵심 수량·대상·요청한 행위의 답이 사라짐.
- 필수 제한·예외·전제 조건이 사라짐.
- “따라서”, “이는”, 비교·추천 등의 문장이 삭제한 주장에 의존함.
- 자료에 없는 부정·혜택·개인 상태 단정이 남음.
- 다른 하위 질문의 답이나 기준 안내만 남음.

“따라서”라는 단어 자체는 폐기 기준이 아닙니다. 삭제된 내용에 실제로 의존하는지가 기준입니다.

## 2.6 구현을 검토한다면

- `AiService`에서 `contentRemoved`만 보고 전체 폐기하는 조건을 바로 제거하지 않습니다.
- 가드 내부에서 세부 삭제 규칙과 영향(핵심 답·조건·의존 문장)을 판단해 보존 가능성을 전달하는 방식이 적절합니다.
- 현재 `OutputGuardResult`에는 제거 문장과 사유의 대응 관계가 없으므로, 이를 확인할 수 있는 내부 결과가 우선 필요합니다.
- 전체 거부 결과는 생성자에서 본문을 `null`로 만들기 때문에, 잔여 없음 20칸은 호출부 조건을 완화하는 것만으로 복구되지 않습니다. 이 중 오탐은 1부처럼 가드 규칙 자체를 고쳐야 합니다.
