## 요약

### 좋아진 점

- **도구를 거치지 않는 답변 경로는 v4 결과를 재현합니다.** 회선 시드 재측정에서 청구·사용량 도구를 부르지 않은 55문항(UD 제외)은 정답 43/53 → 45/55, status 일치 45 → 45입니다. 칸 형식 자체로 인한 저하는 보이지 않습니다.
- **회선 정보로 답하는 질문이 실제로 답변됩니다.** 남은 데이터, 이번 달 요금, 요금제, 약정 만료일, 부가서비스, 결합 여부, 통화 시간, 납부일을 사용자 정보 섹션 그대로 답했습니다(UD-007·008·010·011·016·019·020·021·028).
- **"회선이 없으므로 ~없음" 추론이 사라졌습니다.** 회선 없는 계정(v5)에서 23문항에 나온 이 패턴이 회선이 있는 계정(v6)에서는 0건입니다. 같은 문항 묶음의 환각은 31/172 → 26/170입니다.
- **매장 경로는 안정적입니다.** ST 정답 22/30(v4) → 23/30, 환각 2/30 → 3/30.
- **모델이 쓰는 고지가 거의 없습니다.** v5 전체에서 Judge 고지 검출 13건(v4 8건). 답하지 못한 부분은 코드 고지로 나갑니다.
- **가드·저장 흐름이 끝까지 동작합니다.** 입력·하위 질문·출력 가드, 미응답 수집, DB 저장 답변과 HTTP 답변 일치(356/356)를 확인했습니다.

### 개선해야 할 점

1. **사용자 정보 FAQ가 하나라도 걸리면 청구·사용량 도구가 켜지고, 일반 질문에서도 도구를 부릅니다.**
   - 재측정 172문항 중 111문항에서 194회 호출했습니다. 대부분 "태블릿 20GB 가격", "매장 예약 취소"처럼 회선과 무관한 질문입니다.
   - 도구를 부른 87문항(UD 제외): 정답 67/87 → 50/86, status 일치 70 → 55. 이 묶음이 전체 저하의 대부분입니다.
   - 도구 경로는 출력 스키마가 강제되지 않아, 칸 수가 맞지 않으면 칸을 하나로 합칩니다. 칸을 합친 20문항은 정답 16/20 → 8/20입니다.
   - 도구 왕복만큼 느려집니다. 백엔드 처리 시간 기준으로, 도구를 부르지 않은 문항은 평균 2.3초, 부른 문항은 4.6초입니다. 같은 문항끼리는 v5 2.9초에서 회선 시드 후 3.7초가 됐습니다.
   - 후보: 이전 달 사용량·청구서를 묻는 하위 질문에만 도구를 켜기, 도구 결과를 받은 뒤 스키마를 강제해 한 번 더 호출하기.
2. **칸 파싱 결함으로 실행이 실패합니다.**
   - MN-008(CHAT-015): 칸에 status가 빠지면 `FaqAnswerFormat.readSlots`의 `SLOT_STATUSES.contains(null)`에서 NPE가 납니다.
   - UD-025(LLM-005): 섹션에 있는 청구서를 도구로 다시 조회한 뒤 칸 출력이 깨졌습니다.

4. **사용자 정보 질문의 남은 오류.**
   - 답할 수 있는데 보류: UD-004·009·012·026·029.

   - 기준 청구서 혼동: UD-020·030은 최신 10월 청구서가 섹션에 있는데 도구로 받은 9월 청구서를 기준으로 답했습니다.
   - 날짜 판단 모순: UD-006("2년 7개월이 지났으나 1년을 넘지 않았다").
5. **자료에 없는 값을 부정·0으로 단정하는 문제가 남아 있습니다.** SB·MP의 "유심 판매 불가", "오프라인 저장 불가", "개통비 없음" 등입니다(v4부터 이어진 문제).
