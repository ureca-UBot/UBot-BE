# FAQ HNSW 검색 테스트 보고서

FAQ 벡터 검색을 exact search에서 HNSW로 다시 바꾸면서 2026-10-21에 측정한 결과입니다. 이전에 exact로 바꾼 이유는 [FAQ 검색·답변 테스트 보고서](FAQ_검색_테스트_보고서.md)에 있습니다.

## 결론

1. **FAQ 벡터 1만 건에서 검색이 4~6배 빨라졌습니다.** p50 기준 FAQ 검색 28.82ms → 4.66ms, intent별 검색 21.61ms → 4.66ms입니다. 실제 시드 데이터의 `QUESTION` 벡터는 프로필당 약 9,500건이라 이 구간에 해당합니다.
2. **1천 건에서는 DB가 순차 검색을 골라 약 1.8~1.9배 느렸습니다.** 인덱스는 쓰이지 않고 트랜잭션·설정 비용만 더해집니다.
3. **합성 데이터에서는 exact와 결과가 같았습니다.** 4개 경우 모두 상위 3개 recall과 1위 일치율이 100%였고, topK보다 적게 돌려준 요청도 없었습니다.
4. **상담 금지 문장 검색은 exact를 유지합니다.** 실제 문장 수가 수백 개 이하라 같은 측정(1천 건)에서도 순차 검색이었고 3.06ms → 6.63ms로 느려졌습니다. 근사 검색이 가장 가까운 금지 문장을 놓치면 차단할 메시지가 전달되므로, 이득 없이 위험만 늘어납니다.

## 바꾼 점

- 예전 HNSW 문제는 인덱스가 후보(`ef_search` 기본 40개)를 고른 뒤 프로필·유형 조건을 적용해, 조건에 맞는 벡터를 놓치는 것이었습니다.
- pgvector 0.8의 iterative index scan을 켜서(`hnsw.iterative_scan=strict_order`, `hnsw.ef_search=200`) 필터로 후보가 빠지면 추가로 탐색합니다. 설정은 검색 트랜잭션에만 적용합니다(`set_config(..., true)`).
- 거리 오름차순 + LIMIT으로 후보를 가져오고, 후보 안에서 FAQ별 최고 점수 표현을 고릅니다. 중복 제거 후 topK가 모자라면 후보 수를 40개부터 두 배씩 늘립니다.
- 프로필·벡터 유형·FAQ 버전·삭제 여부·intent 조건과 API 응답 형태는 그대로입니다.

## 측정 조건

| 항목 | 조건 |
|---|---|
| DB | PostgreSQL 18.6, pgvector 0.8.6 (Testcontainers 전용 DB, 전체 Flyway 적용) |
| 데이터 | 테이블별 벡터 1,000 / 10,000건, 1,024차원 합성 벡터(64개 군집). 다른 프로필·유형·구버전·삭제 FAQ 포함 |
| 검색 | FAQ 전체, `GENERAL` intent FAQ. topK=3 |
| 반복 | 질문 벡터 40개 × 5회 = 경로별 200회, 실행 순서 교대 |
| 측정 구간 | 저장소 호출 시간(JDBC·트랜잭션·설정·후보 확장 포함). 임베딩 생성·LLM 제외 |

## 결과

단위는 ms입니다. 배율은 `exact p50 / HNSW 경로 p50`이고 1보다 작으면 느려진 것입니다.

| 벡터 수 | 검색 | exact p50 | HNSW 경로 p50 | exact p95 | HNSW 경로 p95 | 배율 | 인덱스 사용 |
|---:|---|---:|---:|---:|---:|---:|---|
| 1,000 | FAQ | 3.23 | 5.75 | 4.03 | 7.02 | 0.56배 | 아니요 |
| 1,000 | FAQ intent | 2.32 | 4.52 | 2.81 | 5.21 | 0.51배 | 아니요 |
| 10,000 | FAQ | 28.82 | 4.66 | 41.57 | 6.34 | 6.19배 | 예 |
| 10,000 | FAQ intent | 21.61 | 4.66 | 24.43 | 5.58 | 4.64배 | 예 |

상담 금지 문장 수치는 같은 날 앞선 측정(검색 설정을 `SET LOCAL` 두 번으로 보내던 시점)의 결과입니다.

FAQ HNSW 인덱스(`idx_faq_embeddings_vector_hnsw`)는 V23부터 있던 인덱스이며 1만 건에서 약 78MiB입니다.

## 남은 확인

- 이번 recall은 합성 벡터 결과입니다. 이전 보고서와 같은 실제 질문 105개와 실제 FAQ 임베딩으로 exact 대비 상위 3개 차이를 다시 재서, 0건인지 확인해야 합니다.
- iterative scan의 탐색 상한(`hnsw.max_scan_tuples`, 기본 20,000)은 기본값입니다. 임베딩 프로필을 바꾼 뒤 이전 프로필 벡터를 오래 남겨 두면 필터로 버려지는 행이 늘어 topK보다 적게 돌려줄 수 있습니다.

## 다시 측정하기

```powershell
.\tools\perf\run-vector-search-benchmark.ps1
```
