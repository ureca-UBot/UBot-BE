# FAQ 검색·답변 테스트 보고서

FAQ 질문+답변(Q+A) 임베딩을 추가하면서 2026-10-12 ~ 10-13에 로컬 개발 환경에서 한 테스트 결과입니다.

> 이후 FAQ 검색은 pgvector iterative scan으로 HNSW를 다시 사용합니다. [FAQ HNSW 검색 테스트 보고서](FAQ_HNSW_검색_테스트_보고서.md)를 참고하세요.

## 결론

1. **FAQ 검색은 HNSW 인덱스 대신 전체 비교(exact search)로 바꿨습니다.** 인덱스를 쓰면 Q 검색은 105개 중 6개, Q+A 검색은 60개에서 더 가까운 FAQ를 놓쳤습니다. 바꾼 뒤에는 0개이고 검색 한 번에 5~17ms입니다.
2. **Q+A가 Q보다 항상 좋은 것은 아닙니다.** 등록한 FAQ 100건에서는 Q+A가, 기존 FAQ 1,000건에서는 Q가 낫습니다. 검색 유형 기본값은 `QUESTION`으로 두었습니다.
3. **Q+A를 쓰려면 유사도 기준을 낮춰야 합니다.** 기준 0.75에서는 정답 FAQ가 100건 중 11건만 LLM에 전달됩니다. 0.65 부근이 맞습니다.
4. **오답의 주된 원인은 FAQ 데이터입니다.** 기존 FAQ 1,000건은 Ubot이 아닌 다른 상품 체계를 설명하고 있어서, 등록한 Ubot FAQ와 같은 질문에 다른 답이 함께 들어 있습니다.

## 환경

| 항목 | 값 |
|---|---|
| 백엔드 | `develop`(`f2c8d09`)에 Q+A 임베딩과 exact search 변경을 적용한 상태 |
| FAQ | 활성 1,124건 = 기존 1,000건 + 내 정보용 24건 + 등록 100건(`ubot-faq-100.json`, ID 1025~1124) |
| 임베딩 | `ubot-embedding`(bge-m3, vLLM). Q 벡터와 Q+A 벡터 각 1,124건 |
| 답변 모델 | `ubot-chat`(Qwen3-4B, vLLM) |
| 검색 | Top-K 3. 유사도 기준은 테스트마다 표기 |

판정(정확, 부분, 오답 등)은 답변을 기대 답변과 대조해 사람이 직접 매긴 것입니다.

## 1. 검색 방식: HNSW와 exact search

같은 질문 105개(등록 FAQ 변형 100개 + 등록하지 않은 내용 5개)로, 백엔드 검색 쿼리를 그대로 실행해 비교했습니다.

| 지표 | Q: HNSW → exact | Q+A: HNSW → exact |
|---|---|---|
| 검색 상위 3개에 정답 FAQ 포함 (100건 중) | 62 → 66 | 68 → 83 |
| 검색 결과가 3개 미만 (105건 중) | 0 → 0 | 59 → 0 |
| 검색 결과가 0개, `CHAT-012` (105건 중) | 0 → 0 | 16 → 0 |
| 인덱스 없이 계산한 상위 3개와 다름 (105건 중) | 6 → 0 | 60 → 0 |

- 원인: `faq_embeddings`의 HNSW 인덱스 하나에 모든 Profile과 유형의 벡터가 함께 들어 있고, Profile·유형 조건은 인덱스가 후보(`hnsw.ef_search`, 기본 40개)를 고른 뒤에 적용됩니다.
- `ef_search`를 올려도 해결됩니다. Q / Q+A가 놓친 질문 수는 40에서 6 / 60, 100에서 2 / 16, 200 이상에서 0 / 0입니다.
- 적용한 방법: 검색 쿼리가 거리 연산자 대신 유사도로 정렬하게 해서 인덱스를 타지 않게 했습니다. 스키마는 바꾸지 않았습니다.
- 실제 채팅 확인: 전에 미응답이던 "컬러링 한 달 요금 얼마예요?"가 정답 FAQ(유사도 0.788)를 찾아 답합니다.
- 미응답 질문을 묶는 검색은 바꾸지 않았습니다.

## 2. Q와 Q+A의 Hit@K

정답 FAQ가 상위 K개 안에 들어온 건수입니다. 모두 exact search 기준입니다.

| 질문 세트 | 건수 | Q: Hit@1 / 3 / 5 / 10 | Q+A: Hit@1 / 3 / 5 / 10 |
|---|---|---|---|
| 기존 FAQ 1,000건 변형 | 1,000 | 901 / 969 / 981 / 987 | 799 / 932 / 962 / 976 |
| 등록 FAQ 100건 변형 | 100 | 52 / 66 / 73 / 89 | 58 / 83 / 91 / 95 |
| 다양한 표현 중 등록 FAQ | 56 | 27 / 32 / 37 / 42 | 27 / 43 / 48 / 52 |
| 다양한 표현 중 기존 FAQ | 28 | 23 / 27 / 28 / 28 | 22 / 26 / 27 / 28 |

- 기존 FAQ에서는 Q가 모든 K에서 높고, 등록 FAQ에서는 Q+A가 높습니다.
- 위 두 줄(1,000건 + 100건)을 합치면 Hit@3은 Q 94.1%, Q+A 92.3%이고 Hit@5는 95.8%, 95.7%입니다.
- 정답 FAQ의 유사도 평균은 Q+A가 낮습니다. 기존 FAQ 세트에서 Q 0.879, Q+A 0.721이고 등록 FAQ 세트에서 Q 0.773, Q+A 0.688입니다.

기존 FAQ 1,000건 세트의 표현별 결과입니다(각 200개, Hit@1 / 3 / 5 / 10).

| 표현 | Q | Q+A |
|---|---|---|
| 바꿔 말하기 | 195 / 199 / 199 / 200 | 187 / 197 / 199 / 199 |
| 키워드·단문 | 182 / 195 / 197 / 199 | 161 / 194 / 199 / 200 |
| 반말·붙여 쓰기 | 196 / 199 / 200 / 200 | 181 / 195 / 198 / 199 |
| 상황 설명 | 183 / 195 / 198 / 199 | 154 / 187 / 198 / 199 |
| 돌려 말하기 | 145 / 181 / 187 / 189 | 116 / 159 / 168 / 179 |

핵심 단어를 피해 돌려 말한 질문이 두 방식 모두 가장 약합니다.

## 3. 유사도 기준

정답 FAQ가 상위 3개 안에 있으면서 기준 이상이어야 LLM에 전달됩니다.

등록 FAQ 100건 변형 세트입니다. "미등록"은 등록하지 않은 내용을 묻는 5건 중 답변 단계로 넘어가는 수입니다.

| 기준 | Q 전달 | Q 미등록 | Q+A 전달 | Q+A 미등록 |
|---|---|---|---|---|
| 0.60 | 66 | 5 | 80 | 5 |
| 0.65 | 66 | 5 | 69 | 4 |
| 0.70 | 62 | 5 | 45 | 2 |
| 0.75 | 54 | 4 | 11 | 1 |
| 0.80 | 35 | 1 | 2 | 0 |

기존 FAQ 1,000건 변형 세트입니다.

| 설정 | Top-K 3에서 전달 | Top-K 5에서 전달 | 미응답 |
|---|---|---|---|
| Q, 기준 0.75 | 905 | 908 | 66 |
| Q+A, 기준 0.65 | 832 | 847 | 122 |

- Top-K를 3에서 5로 늘려도 전달되는 수는 거의 늘지 않습니다.
- Q+A는 기준을 0.60으로 내리면 Top-K 3에서 898건이 전달됩니다.

## 5. 기존 FAQ의 상태

| 묶음 | 건수 | 답변 평균 길이 | 답변에 숫자가 있는 건수 | "Ubot"이 나오는 건수 |
|---|---|---|---|---|
| ID 1~100 | 100 | 37자 | 1 | 0 |
| ID 101~1000 | 900 | 58자 | 345 | 0 |
| ID 1025~1124 (등록 FAQ) | 100 | 79자 | 87 | 82 |

- **기존 FAQ에는 Ubot 상품명이 한 건도 없습니다.** ID 1~100은 숫자 없는 일반론이고, ID 101~1000은 5G 프리미엄, LTE 세이브, 시니어 LTE, 넘버플러스, 구독팩 같은 다른 상품을 설명합니다.
- **같은 질문에 다른 답이 함께 있습니다.**

| 질문 | 기존 FAQ | 등록 FAQ |
|---|---|---|
| 결합 할인을 회선마다 받나요? | 914: 회선마다 적용, 3회선이면 각 5,500원 | 1075: 결합 전체 금액, 대표 1회선에서만 할인 |
| 데이터 추가 가격 | 136: 1GB 5,500원, 5GB 16,500원 | 1105~1107: 1GB 3,300원, 5GB 9,900원 |
| 무료 부가서비스 | 748: 착신 전환 포함 | 1094: 착신 전환 없음(월 1,100원) |

- **기존 FAQ는 Q+A로 만들면 서로 더 비슷해집니다.** 각 FAQ와 가장 가까운 다른 FAQ의 유사도 평균이 Q 0.809, Q+A 0.851이고, 0.90 이상인 이웃이 있는 FAQ가 Q 20건, Q+A 216건입니다.
- 답변에 같은 문구가 반복되는 것이 원인으로 보입니다. ID 101~1000의 답변 900건 중 "앱"이 들어간 것이 341건이고, "~수 있습니다 / 확인해 주세요"로 끝나는 것이 318건입니다. 따로 실험해 확인한 것은 아닙니다.

## 6. 그 밖에 확인한 것

- 백엔드 전체 테스트 951개가 통과했습니다. exact search 회귀 테스트는 예전 쿼리로 돌리면 결과 0건으로 실패합니다.
- Q+A 벡터 백필: 1,124건에 약 30초(vLLM)가 걸렸고, 다시 실행하면 0건입니다.
- 답변에 `[FAQ ID: n]`이 그대로 나온 경우가 Q 실행에서 5건, Q+A 실행에서 4건 있었습니다.

## 7. 남은 일

- FAQ 데이터 정리: 요금제, 결합상품, 부가서비스, 로밍처럼 Ubot 상품과 겹치는 기존 FAQ를 Ubot 기준으로 고치거나 빼야 합니다.
- Q+A 전환 여부와 기준값: 데이터를 정리한 뒤 다시 재야 합니다. 답하면 안 되는 질문을 더 넣어야 기준을 정할 수 있습니다.
- 비교·복합 질문과 짧은 키워드 질문에 약합니다.
- 내 정보 질문에 사용자 데이터가 들어가지 않습니다.

## 감안할 점

- 변형 질문은 FAQ 질문만 보고 썼습니다. 답변은 보지 않았으므로 Q 쪽에 유리하게 나왔을 수 있습니다.
- Hit@K는 질문을 만든 그 FAQ가 나와야만 성공으로 셌습니다. 기존 FAQ에는 내용이 비슷한 FAQ가 여럿 있어 실제 체감보다 낮게 나옵니다.
- 답하면 안 되는 질문은 5~27개로 적습니다.
- 모든 측정은 로컬 개발 DB 한 곳에서 한 번씩 했습니다.
