# 입력·출력 AI 가드 연결

> 코드 기준: `develop` `4a7a546faa189946bb48bb14e364750d653b0774` · 2026-10-26

입력 코드 검사 뒤에 안전 판정과 질문 정리를 연결하고, 출력 코드 검사 뒤에 출력 AI 판정을 연결합니다. 가드 전 생성 답변과 출처별 검사 이력·보류 재검토는 [관리자 검토](guard-review.md)에서 이어서 설명합니다.

## 호출 순서

1. `ChatInputGuardService`의 기존 정리·금칙어·주입 검사에서 위험 요구를 탐지하면 질문 전체를 거절한다. 정상 질문이 섞여도 일부만 넘기지 않는다.
2. `SubQuestionPlanner`가 기존 `QuestionRouter`로 경로를 고른다. 질문 분리·멀티턴 표지가 있으면 기존 분류기 호출 지점에서 안전 판정과 검색어 정리를 한 번의 AI 호출로 수행한다. 원문 검색 경로와 `CHAT_SUB_QUESTION_ENABLED=false` 경로에는 별도 보조 AI 검사를 붙이지 않는다.
3. 원문 검색이 충분하면 통합 AI를 호출하지 않는다. 원문 검색이 부족하면 기존 judge 분기에서만 통합 AI를 한 번 호출한다. 통합 AI를 호출한 경로에서는 ALLOW일 때만 기존 `SubQuestionGuard`·`MultiTurnDetector`·검색·답변 생성으로 진행한다. 질문 정리를 껐으면 검색 실패 뒤에도 기존처럼 원문을 사용한다.
4. 생성된 답변은 기존 `FaqAnswerFormat` 파싱 → 칸별 출력 코드 검사 → 최종 답변 합치기 → 출력 AI 검사 1회 순서로 처리한다. 코드 검사의 `POLICY_VIOLATION`은 전체 요청을 거절한다. 그 외 거절·문제 내용 제거는 해당 칸 전체를 `ABSTAIN`으로 바꾸고 정상 칸을 유지한다. 일반 본문은 문제 내용 제거·거절 시 전체 거절한다. 출력 AI의 BLOCK은 합친 최종 답변 전체를 거절한다. 전달할 본문이 없거나 코드가 전체 거절하면 출력 AI를 호출하지 않는다. 모델 자체의 ABSTAIN·CONFLICT와 조회 실패 안내는 유지하며, 가드가 만든 ABSTAIN을 모델 자체 미응답으로 저장하지 않는다.
5. 공식 FAQ 캐시 답변은 출력 코드 검사만 거친다. 캐시 적중 시 답변 생성·출력 AI를 호출하지 않는다.

문장 경계와 개별 규칙은 탐지에 계속 사용하지만, 문제 내용이 검출된 검사 단위의 정상 문장만 반환하지 않는다. 다만 “추가로 궁금한 사항이 있으면 알려주세요” 같은 단순 마무리는 코드 가드가 정리하고 본문을 유지한다. 실제 추가 정보를 요구하는 질문은 계속 거절하며, 사용자 지시로 붙인 `REQUESTED_SUFFIX`도 차단을 유지한다. 출력 AI는 답변을 삭제·재작성하지 않고 정리된 최종 답변만 판정한다. 근거 번호 오타·누락은 기존 경고 정책을 유지하며 본문 검사는 실제 제공 자료로 수행한다. 표시용 FAQ 참조 정리와 안전성 위반은 구분한다.

## 판정과 오류

| 판정 | 처리 |
|---|---|
| 입력 BLOCK | `CHAT-022`, 질문 전체 거절 |
| 출력 BLOCK | `LLM-006`, 답변 전체 거절·재시도 금지 |
| 입력·출력 REVIEW | `LLM-008`, 허용하지 않고 보류 오류로 종료·재시도 금지 |
| 잘못된 JSON·알 수 없는 필드/사유·잘린 응답 | `LLM-005`, 허용·원문 검색으로 대체하지 않음 |
| 연결·응답 시간 초과·슬롯 포화 | 기존 `LLM-003/004/007` 오류 전파 |

REVIEW는 관리자 분석 기능에 자동 등록하는 의미가 아니다. 이번 변경에 관리자 위험 표현 분석 기능은 포함하지 않는다. 실패 시 사용자에게 답변을 노출하지 않으며, 기술적 실패에 대한 기존 재시도 정책은 유지한다. 가드 자체는 자동으로 모델을 다시 호출하지 않는다.

입력 안전 판정이 OFF인 분류 전용 경로에서는 기존처럼 분류기의 시간 초과·포화·잘못된 응답을 원문 검색(`Source.LLM_FAILED`)으로 복구한다. 활성 통합 안전 판정의 BLOCK·REVIEW·실패는 복구하지 않는다. 취소도 그대로 전파한다. 이전 대화 조회의 DB 실패는 가드 스위치와 관계없이 `STORAGE_UNAVAILABLE`로 종료한다.

입력·출력 AI 로그에는 단계·판정·정의된 사유·처리 시간만 기록한다. 질문·답변·근거 원문·모델 설명은 기록하지 않는다. 가드 전송 오류의 응답 본문과 원본 예외도 로그·예외 원인에서 제외한다.

## 모델과 프롬프트

실험에서 선택한 체크포인트는 `RedHatAI/Qwen3-4B-Instruct-2507-quantized.w4a16`이며, 실제 API 모델명은 `AI_GUARD_MODEL` 설정을 따른다. 미지정 시 실행 환경의 답변 생성 엔진·주소·API 모델명을 사용한다. 답변 생성 모델의 선택·프롬프트·기존 답변 JSON 파서는 변경하지 않는다.

“기존 분류 유지”는 Router의 호출 조건, 질문 정리 역할, 후단 검색어 보호·멀티턴 처리를 재사용한다는 뜻이다. 안전 판정이 ON이면 기존 `SubQuestionPromptService`·스키마 대신 선택한 통합 프롬프트·스키마로 가드 모델이 검색어를 만든다. 따라서 분리·빈 자리 채우기 결과나 검색 품질이 기존 분류기와 같다고 보장하지 않는다. OFF일 때만 기존 분류 전용 프롬프트·스키마·답변 생성용 모델을 사용한다.

실험 원본을 재작성하지 않고 아래 리소스로 복사했다. 줄바꿈은 실제 실험 요청과 같은 LF로 통일했다. 원본 파일과 배포 리소스의 SHA-256은 [provenance.json](../../src/main/resources/prompts/ai-guard/provenance.json)에 함께 기록했다. 해당 리소스의 체크아웃 줄바꿈만 `.gitattributes`로 고정한다.

| 리소스 | 선택한 원본 |
|---|---|
| `input-integrated-system.txt`, `input-integrated-schema.json` | `work/input-ai-threeway363-20261023-side/joint-*` — 기존 363건·추가 300건에서 사용한 통합형 |
| `output-safety-system.txt`, `output-safety-schema.json` | `outputs/guard-quick363-20261022-side/prompt.txt`, `schema.json` — 유지하기로 한 전체 답변 판정 |

성능이 나빠진 입력 178건 보완본과 출력 grounding24 보완본은 사용하지 않는다. 서비스 검사·프롬프트에 사례 ID·기대 판정·특정 FAQ 예외를 추가하지 않았다.

## 연결 값

환경·배포 파일을 수정하지 않고 기존 설정 방식에 선택적 가드 값을 추가했다.

| 값 | 기본값 |
|---|---|
| `AI_GUARD_ENGINE`·`AI_GUARD_BASE_URL`·`AI_GUARD_MODEL` | 실행 환경의 답변 생성 엔진·주소·API 모델명 |
| `AI_GUARD_CONNECT_TIMEOUT` | 기존 `LLM_CONNECT_TIMEOUT`, 없으면 `3s` |
| `AI_GUARD_READ_TIMEOUT` | 기존 `LLM_READ_TIMEOUT`, 없으면 `120s` |
| `AI_GUARD_MAX_CONCURRENT` | 기존 `LLM_MAX_CONCURRENT`, 없으면 `4` |
| `AI_GUARD_PERMIT_WAIT_TIMEOUT` | `5s` |
| `AI_OUTPUT_GUARD_MAX_TOKENS` | `1024` (허용 `1024~4096`) |

같은 서버면 답변 생성과 가드가 기존 동시 호출 허가를 공유하고, 별도 서버일 때만 가드 전용 허가를 사용한다. 모델명만 바꾸어도 같은 서버의 상한은 늘지 않는다. 지표는 `client=chat|guard`로 구분한다. 공유 서버의 동시성 게이지는 `client=chat` 하나에 실제 합산 점유를 표시한다. 자세한 값은 [설정 Reference](../reference/configuration.md#입력출력-ai-가드-모델-설정), 지표는 [LLM 지표](../reference/metrics.md#llm)를 따른다.

네 가드 스위치는 기본 ON이다. `AI_INPUT_GUARD_ENABLED=false`는 기존 금칙어·프롬프트 주입 코드 검사도 끈다. 입력 코드를 유지하려면 이 값은 true로 두고 `AI_INPUT_LLM_GUARD_ENABLED=false`만 지정한다. 기존 질문 분류 호출까지 없어지는 것은 아니다.

이 구현 검증에서는 실제 서버에 접속하지 않았으므로, 배포 환경의 모델 제공 여부·메모리·지연·동시 처리 여유는 별도로 확인해야 한다. 서버나 다른 서비스를 실행·중지하지 않았다.

## 저장된 실험 재확인과 검증 한계

2026-10-24 리뷰 대응에서 저장된 `outputs/input-ai-threeway363-20261023-side` 기록을 재확인했다. 통합형과 기존 분류기의 검색어 또는 멀티턴 표지가 달라 검토 대상으로 기록된 건은 29건이다(`classification-changes.json`, `INTEGRATED / REVIEW_OUTPUT_CHANGE`). 차이는 확정 오류 건수가 아니다. 해당 363건은 이전 대화가 모두 비어 있고 임베딩·답변 생성·외부 Judge 호출도 0회이므로, 검색 적중률이나 실제 멀티턴 품질을 검증한 자료로 제시하지 않는다. 이번 모의 연결 테스트와 정리 역할 지침 포함 여부 확인도 실제 모델의 결과 품질을 증명하지 않는다. 같은 FAQ 집합·이전 대화로 기존 분류기와 통합형을 비교하는 실제 검색 품질 검증은 별도로 남는다.

저장된 `outputs/output-sts-two172-20261024-side/llm-results.jsonl`의 실제 호출 154회는 출력 토큰 최소 66·p95 159·최대 199였고 모두 `stop`으로 끝났다(요청 상한 320, 잘림 0회). 이 기록은 현재 칸별 답변 합치기의 모든 길이를 대표하지 않는다. 프롬프트·스키마의 원본과 한국어 설명 최대 240자는 유지하고 생성 상한만 기본 1024로 늘렸다. 상한을 늘려도 잘림이 불가능해지는 것은 아니며 `finish_reason=length`는 계속 `LLM-005`로 처리한다. 출력 상한 변경은 입력 판정 512나 답변 생성 한도에는 적용하지 않는다.

## 초기 연결 검증 기록 (보조 검사 제거 전)

2026-10-23 로컬 Java 21 컴파일과 캐시된 의존성으로 관련 단위·연결 테스트 47개 클래스, 2,800건을 실행해 모두 통과했다. 새 AI 연결·전송·모델 위임·프롬프트 해시 검사는 그중 33건이다.

이 수치는 별도 보조 검사가 포함됐던 초기 연결 구성의 기록이다. 이후 순수 통합형으로 변경하면서 별도 안전 검사 호출·전용 모드·프롬프트·스키마를 제거했다. 기존 통합형·출력 가드 프롬프트 문구와 Router·검색·검색어 보호·멀티턴의 기존 처리 조건은 유지한다.

- 전체 입력·출력 차단, 정상 문의·인용·거절·조건 안내 보존, 근거 번호 경고 정책
- ALLOW/BLOCK/REVIEW·시간 초과·잘못된 응답, 코드 차단 시 AI 호출 생략, 원문 검색 경로 검사
- 질문 분리·멀티턴·가입 정보·Outbox 후보·Worker 취소·재시도 금지 관련 기존 단위 테스트
- 실제 모델을 부르지 않는 메모리 전송 모의 검사와 프롬프트·스키마 6개 원본 일치 확인

기존 일부 제거 기대값은 전체 차단 정책에 맞춰 수정했다. 정상 보존 단언은 유지했고, 혼합 답변과 분리된 정상 안내는 별도로 검사한다. 기존 DB 통합 테스트의 새 가드 연결은 모의 응답으로 보완하고 소스 컴파일을 확인했다.

전체 Gradle 빌드·Docker/DB/Redis 통합 테스트·실제 모델 연결·실제 브라우저·EC2·배포 환경의 성능은 이번에 실행하지 않았다. 이 결과는 실제 AI의 미탐률·오차단률을 새로 측정한 결과가 아니다. 별도 입력·출력 실험의 남은 미탐과 오차단 가능성은 그대로 남는다.

## 순수 통합형 연결 검증

별도 보조 검사 제거 전 관련 테스트 250건을 통과했고, 제거 후에는 호출 경로 검증을 보완한 11개 클래스 252건을 모두 통과했다. 전체 운영 소스와 테스트 소스의 Java 21 컴파일도 확인했다.

- 기존 원문 검색이 충분한 경로: 입력 AI 호출 0회
- 기존 원문 검색이 부족한 경로: 기존 판정 지점에서 통합 AI 호출 1회
- 질문 분리·멀티턴 표지가 있는 경로: 기존 판정 지점에서 통합 AI 호출 1회
- 질문 정리 비활성화 경로: 검색 실패 후에도 입력 AI 호출 0회
- 코드 차단·통합 AI의 BLOCK·REVIEW·시간 초과·잘못된 판정 처리와 출력 가드 거절 시 재시도 금지 유지

별도 안전 검사 호출 3곳과 해당 모드·프롬프트·스키마만 제거했다. 기존 Router·검색·검색어 보호·멀티턴 코드와 통합형·출력 프롬프트 및 스키마 4개의 내용은 유지했다. 이 검증은 모의 모델·검색 응답을 사용했으며 실제 LLM·임베딩·DB·EC2 호출이나 서비스 재시작은 수행하지 않았다. 저장된 순수 통합형 100건 실험의 프롬프트와도 문구가 같은지 대조했으며 해당 실제 모델 실험을 다시 실행한 것은 아니다.
